# Changelog

Notable changes to the product, newest first. Each date gets one section, and each entry says what changed for the people who use it (and why, when that isn't obvious). Small internal changes don't need an entry; Git keeps those.

## 2026-11-06

- `npm run check` connects and completes the documents in more places. Each feature `SPEC.md` now links the root `SPEC.md` user stories it implements, and links to a heading must find one, so renaming a story can't silently break the features that point to it. A new `scripts/declared-interfaces.mjs` lets a project read its real routes and messages from the code; once filled in, the check fails when a feature's **Serves** or **Handles** misses one, so the diagrams can't quietly leave a route out. Runtime calls now match whole routes and names, so `/api/tasks/archive` no longer counts as a call to `/api/tasks`, nor `autosave` as the event `save`. `--existing` now stops before changing anything when a project already has its own `scripts/check.mjs` or `scripts/generate-docs.mjs`, instead of failing halfway. The feature spec template says where security, privacy and data-format rules go, the example gained a root `SPEC.md`, and its command line no longer refers to an `npm start` script that doesn't exist.

- Every feature `SPEC.md` now ends with a generated dependency diagram, as in the Focus / dot project this template came from. It shows what the feature imports, the routes, messages or events it calls on other features at runtime, which features use it, and its outside services. Feature specs gain an **Interfaces** section (**Serves**, **Handles**, **Stores**, **Uses**, **External**) that drives the runtime arrows, and `npm run check` makes sure each route or message has exactly one owner. `DEPENDENCIES.md` shows the same runtime calls.

- Fixed: setting up a project no longer rewrites the placeholders inside the template's own test file, which made one test fail in every new project. When a sandbox blocks some folders, the command now creates everything else and lists what it couldn't write.
- `--existing` adds agent-ready-repo to a project that already has files: it keeps them, merges `package.json` scripts and missing `.gitignore` and `CLAUDE.md` lines, and marks documents to merge by hand with setup notes. Checks now skip files Git ignores, so build output and vendored code in existing projects don't cause false alarms.

- New projects are created with one command, `npx -y github:lnmunhoz/agent-ready-repo --name … --description …`, instead of copying this repository and cleaning it up. The project files now live in `template/`, so a new project gets no example code and no template explainer docs. The few things only the project's agent can write are marked with `<!-- setup: … -->` notes, which `npm run check` lists until they're filled in. The example features moved to `example/`.

- Project memory kept in the repository and shared by every agent, so lessons Claude Code learns are there for Codex too (and the other way round). Each feature has its own `MEMORY.md` next to its `SPEC.md` for decisions, traps and dead ends, and the root `MEMORY.md` holds project-wide lessons plus a generated index of the feature memories. A generated `CLAUDE.md` in each feature folder makes Claude Code load that feature's spec and memory automatically. `npm run check` keeps entries dated and the files short. The generator is now `npm run docs:generate`.

- First version of the template: `AGENTS.md`, the root and per-feature `SPEC.md` files, this changelog, the `TODOS.md` task list, a generated `DEPENDENCIES.md`, and `npm run check` to keep them current. Includes a small example task-list app to show how the pieces fit together.
